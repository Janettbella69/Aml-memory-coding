# aml-memory — Agent Memory Leaderboard (AML 记忆之巅) submission

Open-source Methods entry for the Cycle 2 textual-memory track. Deadline: materials by 2026-10-31 23:59 UTC+8; evaluation closes 2026-11-04 23:59 UTC+8; results mid-November.

## What this service is
A participant-hosted HTTP service with two endpoints the evaluator calls:
- `POST /v1/memories/add` (alias `/add`): synchronous ingest; return 200 only after the chunk is persisted and searchable; echo `request_id`, `user_id`, `session_id` exactly; replays of the same `request_id` are idempotent, conflicting replays return 409.
- `POST /v1/memories/search` (alias `/search`): `{query, options?, user_id, top_k}` → `{data:[{id, content, score?, created_at?}]}`; never more than `top_k` items; official runs use `top_k=100`.
- `GET /health`: unauthenticated, any 2xx.
Auth: evaluator sends `X-Api-Key`, `Authorization: Bearer`, or `Authorization: Token`. `MEMORY_API_KEY` env enables it; empty disables (local only).

## Hard rules (from the competition docs; violating any = disqualification)
- Search returns evidence only. It must never generate or disguise an answer.
- Strict isolation by `user_id`. Never read across users/samples.
- Open-source division: if any LLM is used inside the system, use `gpt-4o-mini` (the docs say "during Add"; we apply it to Search too, like ReFind did); any embedding must be `text-embedding-v4`; rerankers are unrestricted; no self-trained/open-weight models. Official Cycle-2 FAQ Q7 (2026-10-08): a pipeline that calls no generative model at all is acceptable — mark the LLM item N/A and declare the real components (embedding/reranker); when a generative model IS called in Add/Search it must be gpt-4o-mini. The embedding restriction (text-embedding-v4) comes from the competition page FAQ 05, not from this Q&A; the organisers confirmed it by email (asked 2026-10-09, reply relayed by the user on 2026-10-15): the qwen3.7 embedding models (`qwen3.7-text-embedding-flash` / `qwen3.7-text-embedding`) may NOT be used — text-embedding-v4 only. The reply was about embedding models only (user, 10-15): rerankers stay unrestricted, so Model Studio's newer `qwen3.7-text-rerank` is allowed as a reranker. FAQ Q14: `options` may contain the correct answer plus distractors; do not blindly treat options as facts or splice all of them into the retrieval text without judgement (we currently append them to the query — measure before freeze).
- Evaluation data: do not log query/memory text, do not train on it, do not analyse it outside the run, delete within 30 days (`RETENTION_DAYS`, swept at startup).
- Public repo + fixed commit hash + attribution of prior work + method card are required at submission. "Undisclosed reuse may be treated as plagiarism": never adapt lines from another entry's code; ideas are fine when attributed in `docs/METHOD_CARD.md` and `NOTICE`.

## Layout
- `app/store.py` one SQLite file per `user_id` under `DATA_DIR/users/ab/cd/<hash>.db` (WAL): `ingest_log` (idempotency by fingerprint), `memories` (one row per turn; `pos` = chunk ordinal × 1000 + index, `event_ms`, `standing` rule tag), FTS5 word index (porter, external content) + FTS5 trigram index (CJK-only turns). Connections cached per file with a lock (LRU 512, idle 120 s). `SCHEMA_VERSION` mismatch fails loudly (no migration; wipe the data dir between versions).
- `app/search.py` evidence assembly: word BM25 (+ trigram BM25 fused by RRF when the query has CJK) → recency band (near-equal scores newest-first) → first `LEAD_HITS` hits, then `RULE_SLOTS` standing rules (query-matching first), then the rest → ±`CONTEXT_WINDOW` spans crossing chunk boundaries, de-duplicated → `MAX_RESPONSE_CHARS` budget → newest-turns fallback. Content rendered as `[YYYY-MM-DD HH:MM UTC] ROLE: text`. The docstring at the top of the file is the authoritative description.
- `app/embed.py` v0.5 dense channel: `text-embedding-v4` through Model Studio's OpenAI-compatible `/embeddings` (batches of 10, token-bucket pacing, retries; failures degrade to lexical and are back-filled by a background loop). Vectors live in `memories.vec` (float16) in the user's own file; `meta` pins model:dims per file; `store.dense_search` is a per-user numpy dot product fused by RRF (`DENSE_WEIGHT`). Enabled by `EMBED_MODEL` + `DASHSCOPE_API_KEY`; the query embedding and the Add-time embedding run outside the SQLite gates.
- `app/timex.py` v0.4 relative-time notes rendered after a turn (`(dates: yesterday = 2025-04-26)`), EN + ZH, derived only from the turn's own timestamp; `TIME_NOTES=0` disables. `OPTIONS_MODE` (append | none | channel) decides how answer options enter retrieval.
- v0.8 fit mode (`FIT_CHARS`, default 0 = off; `search._assemble_fit`): when a user's whole stored text is at most FIT_CHARS characters, Search returns ALL of it as ≤ top_k contiguous segments — the leading `FIT_ANCHORS` hits get a segment grown around them, the rest is cut evenly, segments are ordered by the rank of their best turn and the untouched ones follow in conversation order; every turn appears once. `store.corpus_size` reads per-user turn/char counters kept in `meta` by Add. Proxy for script-shaped memory: `evalset/script_proxy/` + `scripts/eval_script_proxy.py`.
- Request parsing is liberal on purpose (`app/models.py`): a null/odd role, null or object content, an unparseable timestamp ('Unknown', ISO, float), options sent as a string/object/dicts, a missing or out-of-range top_k and a blank query all still get a 200 (an Add 422 is never retried by the platform; a Full run is published only when every task succeeded). `created_at` in results is the hit turn's event time, or omitted — never the storage day, never null. Questions that embed their option list (ScriptMem) are split into stem + options by `search.split_question`.
- `app/rerank.py` v0.7 cross-encoder reranker: one hosted rerank call per Search over the first `RERANK_CANDIDATES` blocks (providers dashscope/voyage/cohere/jina; `RERANK_MODE` replace|rrf); runs before the selector, outside the gate; failure keeps the order. OFF in the submitted configuration (`RERANK_MODEL` empty) since 2026-10-15: measured with the organisers' prompts on top of dense + planner, `qwen3.7-text-rerank` lifted evidence-at-rank-1 (LoCoMo-Refined 0.55 → 0.78, LongMemEval-S 0.62 → 0.75) but not accuracy (LoCoMo 0.704 = 0.704; LongMemEval-S 0.633 → 0.583, knowledge-update 0.80 → 0.50 — replace mode discards the newest-first tie order that update questions need). The 10-09 gain (0.819 vs 0.778, local judge prompt, lexical base) did not survive the official prompts. Module kept, env-gated; `qwen3-rerank` and `qwen3.7-text-rerank` tied on retrieval (LoCoMo 9/9, LongMemEval-S 10/3 of 60).
- `app/selector.py` optional v0.6 evidence selector: one gpt-4o-mini call per Search AFTER retrieval (question + first `SELECTOR_CANDIDATES` blocks → block numbers that hold evidence + question kind fact/task/other); `search.apply_selection` moves them to the front, for 'fact' questions cuts the unselected tail to `SELECTOR_TAIL` (-1 = reorder only; standing rules always kept) and re-issues monotonic scores. Never adds text; any failure keeps the deterministic order. Enabled by `SELECTOR_MODEL` + `OPENAI_API_KEY`. Rationale and numbers: window-arms experiment, PLAN.md 10-09 E.
- v0.9 `search.cap_response` (`RETURN_CHARS`, default 0 = off; `RETURN_FROM_CHARS`): an optional final cut after the reranker and selector, whole blocks, standing rules kept. Measured 2026-10-15 with the organisers' own answer and judge prompts (`scripts/eval_length.py`, prompts parsed from a local clone of their pipelines, never copied into the repo): cutting the list did not help on LoCoMo-Refined and hurt on LongMemEval-S, so it stays off. Lesson: judge with the organisers' prompts before changing what Search returns — our local answer prompt lets the reader abstain, which made long lists look harmful on 10-09.
- `app/planner.py` optional v0.3 query planner: one gpt-4o-mini call per Search (question + first 8 snippets → ≤3 extra keyword queries + date range), fused by RRF; never produces answer text; any failure = deterministic fallback. Enabled only by `PLANNER_MODEL=gpt-4o-mini` + `OPENAI_API_KEY`; the LLM call runs outside the SQLite gate.
- `app/main.py` FastAPI factory `create_app()` (run with `uvicorn --factory`); auth; periodic retention sweep; per-process gates `SEARCH_PARALLELISM=1` / `WRITE_PARALLELISM=2` (SQLite mutex contention makes more threads slower; scale with `UVICORN_WORKERS`).
- `evalset/` our own fictional samples + questions (never leaderboard data); `scripts/eval_local.py` prints hit@k / MRR / trap-order / tokens per capability; `scripts/sweep_local.py` grids env knobs. Every ranking change is judged there first.
- `docs/METHOD_CARD.md` (attribution + method changes per version), `docs/SUBMISSION.md` (form fields), `docs/CHECKLIST.md` (the 8-item gate), `NOTICE` (ReFind MIT notice; the rewritten-baseline history). `deploy/` Caddy + prod compose + runbook; `scripts/soak_local.py` load test.

## Conventions
- Python 3.12, type hints, no new dependencies without a reason written in PLAN.md (numpy added 2026-10-09 for the dense channel's matrix product).
- Any ranking change needs a test in `tests/`, a before/after line from `scripts/eval_local.py`, and a line in `docs/METHOD_CARD.md`.
- Never commit `.env`, keys, or evaluation data. `data/` is git-ignored.
