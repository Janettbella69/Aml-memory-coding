# Full-evaluation checklist

The platform's 8-item gate (wording copied from the Evaluation page on 2026-10-07; the Submit button stays locked until all are confirmed). One note per item on how we meet it or what is still open.

- [ ] **Smoke test completed** — "The Add/Search API has passed the platform smoke test and is currently usable." *Open:* the public deployment is up (`https://memory.azorashopping.site`, TLS, `MEMORY_API_KEY` set); still needs the evaluation-access request and an issued Eval Key; local `scripts/smoke_test.py` passes.
- [ ] **API contract is followed** — "The submitted code and deployed interfaces are wrapped according to the official Add/Search format." *Done in code:* synchronous Add with byte-exact ID echo and `success: true`, idempotent `request_id` (409 on conflicting replay), `data` array never longer than `top_k`, `[]` for unknown users, unauthenticated `/health`; covered by `tests/` (109 tests) and `scripts/smoke_test.py` (run on 2026-10-07 against a key-protected local server: 401 without key, 200 with X-Api-Key/Bearer/Token, 200 on identical replay, 409 on conflicting replay, 422 on a bad body).
- [ ] **Add/Search model rules are understood** — "Open-source Methods entries are expected to use gpt-4o-mini during Add. Commercial Products entries have no Add/Search model restriction." *Our position:* the submitted configuration uses `gpt-4o-mini` as the Search-time query planner (no generative model in Add — FAQ Q7 allows N/A) and `text-embedding-v4` as the only embedding model (dense channel, v0.5); no reranker in the submitted configuration (the v0.7 module is present but off since 2026-10-15 — measured with the organisers' prompts it did not raise accuracy; rerankers would be unrestricted anyway).
- [ ] **Full evaluation capacity confirmed** — "Capacity for storage, bandwidth, and request handling is prepared for the selected track's Full evaluation scale and the entered Add/Search concurrency limits." *Done 2026-10-08:* declared 16/16; 16-way soak through TLS against the deployed box passed with 0 errors (62.5 adds/s, search p99 5.0 s with the planner; numbers in `docs/METHOD_CARD.md`); 34 GB free on the box (need ≥ 20 GB). Before the Full run: wipe the soak data (`deploy/README.md` § Before the Full run).
- [ ] **Deployment information is complete** — "The submitted notes include the deployed API version, endpoints, authentication, capacity, and operational constraints." *Mostly done:* endpoints, health URL, repository URL and version `1.0.0` (tag `v1.0.0`) are filled in `docs/SUBMISSION.md`; still open: repository visibility (private → public) and the tagged commit's hash in the form.
- [ ] **Original work is disclosed** — "Any reused paper, repository, or code is attributed with its original authors, technical report, and the changes made; personal work is identified as such." *Done:* `docs/METHOD_CARD.md` + `NOTICE`. The 0.1 draft's lines adapted from the unlicensed FTS5 baseline were rewritten in 0.2 and the history is disclosed in the card; ReFind (MIT) ideas are listed with the notice.
- [ ] **This is a substantive submission** — "It is not a repeated near-duplicate or a low-quality submission intended to occupy evaluation capacity." *Our position:* single system, one version, smoke runs only as needed, one Full run; the method changes relative to the baseline pattern are listed in the card.
- [ ] **No manipulation or cheating** — "The system does not use prompt injection, benchmark leakage, result manipulation, malicious behavior, or other leaderboard abuse." *Done in code:* Search returns stored evidence only (no answer generation, no instructions in `content`), no hard-coded answers, strict `user_id` isolation, no logging or reuse of evaluation data, local tuning only on our own `evalset/`.
